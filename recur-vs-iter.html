剧情：要求 f(6)。递归像下级问上级：先问 f(5)，f(5) 再问 f(4)…… 问到 f(1)、f(2) 出口后，答案一层层带回来。中间可能重复问同一个人。

已算 / 待算

问题：f(3) 可能被问很多次——重复计算，n 大时会很慢甚至爆栈。
剧情：还是求 f(6)。递推像记账：先记好 f(1)=1、f(2)=1， 再从左到右用前两项推出下一项，一直填到 f(6)。不回头问，也不重复算。
点「下一步」，看表怎么一格格填满
dp[i] = dp[i-1] + dp[i-2]

dp 表（从小到大）

优势：每个下标只算一次，时间 O(n)，没有递归栈爆掉的风险。
同一公式，两种写法。切换语言看完整可运行示例。递归：函数调自己；递推：循环填数组。

      怎么选：能写成「用前面结果推出当前」→ 优先递推/循环；

递归递推

        
方向从大到小问，再归从小到大填

        
出口/边界if n<=2 return 1dp[1]=1, dp[2]=1

        
核心f(n) 调自己dp[i]=dp[i-1]+dp[i-2]

        
风险重复算、爆栈要开数组、想清顺序

        
适合树形、分治、汉诺塔爬楼梯、斐波那契、前缀和

        
Python 递归默认深度约 1000，可 sys.setrecursionlimit无栈限制（受内存）

        
C++ 递归栈空间有限，深递归危险数组循环，安全快

      

    

    
口诀：递归会问会答，递推会填会推。同一公式，两种走法；n 大优先递推。
